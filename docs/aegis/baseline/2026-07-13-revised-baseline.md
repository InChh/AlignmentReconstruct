## 3. 产品 / 需求基线

### 3.1 当前真值

目标目录为 `D:\Programming\C++\Projects\既有线\AlignmentReconstruct`。项目必须使用最新独立 Visual Studio 2026、C++17、x64 动态库配置，不得依赖 ARX 或 MFC。DLL 只导出三个公共入口，使用同名导入库链接。

公共能力有三项：

1. 从行序无关、具有稳定平面主方向的米制 XYZ 点云拟合三维中心线，按中心线 XY
   水平弧长以调用方给定间隔采样，沿确定性局部纵向递增输出并保留实际起终点。支持稀疏无宽度中心线和带宽度点云，至少 10 个有限点及 3 个不同局部纵向锚点；不再要求每个一米分箱至少 3 点。
2. 从按线路前进方向排序的 XYZ 测点重构平面和纵断面。平面输出交点坐标、曲线半径、进口缓和曲线长和出口缓和曲线长；结果同时返回与输入逐点对应的带符号曲率和 `0/1` 直曲属性。调用方可以把该曲率图原样回灌，跳过自动曲率计算、阈值分类和直曲稳定化，但仍使用同一 owner 完成缓和三态识别、线位拟合、优化及整饰；`ReconstructionOptions` 显式支持半径取整、缓长取整和前后缓长相等，默认不整饰以保持原行为；纵断面输出变坡点统一里程、高程和竖曲线半径。
3. 输入 XYZ 测点与完整线路方案（平面和纵断面），按每个测点的同一平面投影里程联合计算拨量与抬落道量。

主单位为米，毫米为派生便捷值。沿里程增加方向右拨为正、左拨为负；`设计高程 - 测点 z` 为抬落道量，正值抬道、负值落道。

自动平面分类的公共默认阈值为 `0.001 1/m`。初始分类稳定化后不再执行“直线点平均曲率 × 5”的动态调整，只在反向曲线和短曲线处理后保留最终 × 6 调整。2026-10-20 增加有界噪声恢复：当动态调整开始仍有候选曲段、结束全部消失，或自动分析产生单点直线段时，在双侧空间支持充分的前提下依次以 2 倍、3 倍首轮曲率窗口重估同一自动流程。HorizontalReconstructor 复用同一拟合与最终线元闭合校验，仅采用完整有效候选，候选均失败则执行原分析并保留其成功结果或失败诊断。切向角采用圆周平均，切线拟合支持精确及近轴向而不强制吸附。保留原始有序测点，具备有效切线支持的正常自动结果及人工曲率图不做额外分类恢复；不改变默认阈值或引入第二套线路重构。

### 3.2 不可协商项

1. 公共头文件和生产 DLL 仅依赖 C++17 标准库。
2. 平面与纵断面都必须是真实重构，不得用占位、硬编码或仅折线近似替代。
3. 纵断面方案必须包含竖曲线半径，否则不能完整复现现有高程和抬落道计算。
4. 拨量和抬落道量共享同一个平面投影里程。
5. 平面评估必须覆盖直线、进口缓和曲线、圆曲线和出口缓和曲线。
6. 校验失败提供稳定、可定位的诊断，不能静默丢弃测点；非空曲率图必须与测点一一对应、曲率有限、属性为 `straight(0)` 或 `curve(1)` 且分段形状可拟合，不能静默改写调用方属性。
7. 兼容性结论必须有逐字段数值证据和新鲜构建结果。

### 3.3 非目标

- CAD 绘图、实体、命令、MFC 对话框和字符串选项、MDB、Excel、项目管理；对话框已确认的纯数值重构语义可通过公共 options 承载。
- 回头、自交、分岔或沿稳定全局纵向不单值点云的通用自动寻路。
- 三维最短空间距离或综合移动量。
- 集成回旧 ObjectARX 插件。
- VS2012/v110 ABI 兼容。

## 4. 架构 / 运行时边界基线

### 4.1 当前真值

新项目是抽取后纯数值行为的唯一生产所有者。旧工程只作为行为证据。测试专用 `legacy_reference` 可以保留最小参考公式，但不能被生产库链接或成为第二个生产实现。

已实施的权威所有者：

- 公共契约：`include/alignment_reconstruct`。
- 平面重构：`HorizontalReconstructor`，包括自动直曲图生成、调用方直曲图续接、缓和三态识别，以及三变量优化后的等缓长和半径/缓长取整。
- 纵断面重构：`VerticalReconstructor`。
- 平面建线和投影：`HorizontalAlignment`。
- 纵面按里程求高程：`VerticalAlignment`。
- 联合拨量和抬落道编排：`AlignmentAdjustmentCalculator`。
- 点云空间分箱、鲁棒局部拟合和等间隔采样：`PointCloudFitter`。
- 旧行为参考：仅限 `tests/legacy_reference`。

依赖方向为：公共自由函数 → 内部编排所有者 → `HorizontalAlignment` / `VerticalAlignment` → typed 数学线元。`tests/legacy_reference` 只被测试项目编译，不在 `AlignmentReconstruct.vcxproj` 中。

### 4.2 架构不可协商项

1. 生产代码不包含旧仓库源文件。
2. 所有旧全局参数必须转化为显式选项或被证明为不需要。
3. `HorizontalAlignment` 是投影里程唯一权威来源。
4. `VerticalAlignment` 是设计高程唯一权威来源。
5. 联合计算器只编排，不复制平面或纵面公式。
6. 竖曲线半径作为纵断面重构输出和方案输入使用同一语义，可闭环回灌。
7. `include/alignment_reconstruct/api.h` 是 DLL 可见性唯一 owner；只有三个公共自由
   函数导出，内部 `detail::*` 不跨越 DLL 边界。

## 6. 当前状态与风险

项目已建立 `AlignmentReconstruct.sln`、VS2026 `v145` C++17 x64 DLL、导入库、
自包含测试程序和公共 API 样例。点云中心线拟合与采样、平面重构、纵断面重构、
typed 直线/圆曲线/Euler 缓和曲线、最近投影、拨量、竖曲线求高程、抬落道量和
诊断结果都有独立生产实现。

已知边界：点云拟合会自动估计稳定平面主方向，但要求线路沿该局部纵向单值展开并有足够的
局部纵向支持，不是任意拓扑寻路。稀疏数据使用自适应局部窗口和归一化多项式，按横向分布区分有界宽带与中央集中的散点：前者以共享二次中心、线性半宽的联合稳健分位模型估计几何中心，后者使用既有鲁棒中心趋势。断面随中心趋势迭代定位，高程保留点数加权鲁棒拟合；2026-10-20：稀疏及密集宽带若完整支持空间横断面结构，增加断面方向恢复及非均匀间距二阶修正，以保留曲率形状；全部原始观测继续用于偏移与高程求取，不采用行序、固定断面点数或预设线路参数。未满足结构证据的密集数据保留既有数值路径。既有现场 XLSX 只有 N/E 没有 z，因此现场线路重构数据只能直接证明平面
重构、投影和拨量兼容性；纵断面和抬落道量使用确定性 XYZ、旧圆竖曲线公式和回灌
闭环验证。尚未执行 AutoCAD 宿主冒烟，因为新库的明确边界是无 CAD 依赖，且本目标
不包含集成回旧插件。公共 STL 类型跨 DLL 边界要求调用方使用兼容 MSVC C++ ABI、
x64 和匹配的 Debug `/MDd` 或 Release `/MD`；旧静态库交付语义已退役。
`ReconstructionOptions` 于 `2026-08-12` 在末尾增加三个平面整饰字段；调用方需要用新头文件重新编译，
并配套部署同版本导入库和 DLL，不承诺新旧结构体布局的二进制兼容。
`reconstruct` 于 `2026-08-13` 增加第三个可选曲率图参数，`ReconstructionResult` 增加逐点曲率图；
函数符号和结果布局再次变化，同样要求调用方重新编译并配套部署。

## 7. 兼容边界

兼容表示：在受支持且有效的输入上，与选定旧算法的交点、半径、缓长、变坡点、竖曲线半径、投影里程、拨量、设计高程和抬落道量在规定容差内一致。它不表示旧 ABI、CAD 对象、DWG、MDB、界面或未定义边界行为兼容。

## 8. 对齐使用

改变公共字段、单位、符号、输入范围、输出能力或验收标准前，必须重读产品基线。改变所有者、依赖方向、测试参考隔离、兼容或旧代码退役边界前，必须重读架构基线。两者同时变化时报告 `scope: both`。
