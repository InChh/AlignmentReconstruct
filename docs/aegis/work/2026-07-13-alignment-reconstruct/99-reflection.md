# AlignmentReconstruct 完成反思

日期：`2026-07-13`

## 关键判断

本目标的核心不是复制旧文件，而是保留旧活跃数值语义并重新建立单一生产所有者。最重要的边界是平面投影 station 只由 `HorizontalAlignment` 产生，拨量和纵面设计高程共享该 station。

## 避免的错误实现

- 没有把折线最短距离当成圆曲线/缓和曲线投影。
- 没有用综合三维距离取代有方向的拨量和抬落道量。
- 没有让生产库读 XLSX/MDB，也没有将现场方案硬编码进重构器。
- 没有将 `tests/legacy_reference` 变成第二个生产所有者。
- 没有误报 XLSX 中不存在的 z/纵面现场证据。

## 实施中最有价值的证据

- `getpxy_DATA` / `xlzbxy` / `PROJ_ML` / `RectificationSign` 确立平面线元、投影和右正左负。
- `MLToH_Bas` / `VerticleArc` / `CalTLDL` 确立物理圆竖曲线、设计高程和正抬负落。
- 1569 点 MDB 对照将 N/E 映射、station、拨量符号和平面重构同时锁定。
- 发布/调试两种配置的同一组 29 项测试防止仅 Debug 可用，其中包含重构后移动交点再计算拨量的公共 API 回归。

## 流程偏差记录

实施计划中的“单独保存每一阶段 RED 日志”没有被选为 strict TDD 强制路线；本会话使用了分阶段构建、失败修复和即时回归，最终产物由全新构建和独立夹具验证。这是过程证据完整性偏差，不改变产品验收边界，也不用它替代当前新鲜测试。

## 后续触发条件

- 如果用户提供带 z 的现场测点、纵断面方案和抬落道量表，下一个最有价值的验证是将它们导出为第二组独立现场夹具。
- 如果未来集成回旧插件，必须新建明确的 adapter 目标，不得将 ARX/MFC 类型泄漏到当前公共契约。
- 如果未来要退役旧算法，需单独授权、调用点迁移和 AutoCAD 宿主冒烟证据。
