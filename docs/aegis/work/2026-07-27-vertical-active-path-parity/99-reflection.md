# 纵断面活跃路径迁移与 MDB 一致性 - Reflection

这次差异的根因不是现场测点波动，也不是应该放宽容差，而是纵面算法权威入口判断错误。用户提供的参考项目真实运行参数和同次输出坡度表，把可达路径明确收敛到 `CRebuildDlg` → `CReBuildGMX`。

按该路径恢复 15 m 搜索、二阶差商乘 100、交点最小坡长约束、余弦与前后限位边界、全部内部变坡点取整以及 30000 m 半径上限后，完整公开 XYZ 接口使用全部 1569 点得到 55 个纵面控制点。station 和 elevation 最大误差分别为 `4.284e-7 m` 与 `4.930e-7 m`，半径逐点完全相同。

实现仍保持单一 `VerticalReconstructor` owner、纯 C++17 和显式 options，没有读取参考数据库、硬编码结果或保留另一套生产算法。真实运行证据也说明：只比较最终控制点数量不够，平面缓和曲线区间参与竖缓避让，必须经完整 XYZ 接口验证才能得到三个被移动到参考位置的变坡点。
